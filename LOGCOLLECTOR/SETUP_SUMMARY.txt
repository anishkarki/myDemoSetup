📦 WHAT GETS COLLECTED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

FROM PATRONI (BOTH NODES):
  ✓ Patroni daemon logs
  ✓ Patroni configuration files
  ✓ Docker container logs
  ✓ Cluster state snapshots (pre & post event)
  ✓ Failover/switchover history

FROM POSTGRESQL (BOTH NODES):
  ✓ PostgreSQL server logs
  ✓ Replication statistics
  ✓ Configuration (SHOW ALL)
  ✓ WAL position and lag information

FROM INFRASTRUCTURE:
  ✓ HAProxy routing logs
  ✓ etcd consensus logs
  ✓ Container health status

├── cluster_state/         # Cluster metadata & history

└── SUMMARY.txt            # Complete event summary

Plus a compressed archive: event_YYYYMMDD_HHMMSS.tar.gz

OPTION A - Automated Testing (Easiest):
  1. ./check_health.sh                 # Verify cluster is healthy
  2. ./trigger_switchover.sh           # Test planned switchover
  3. Review logs in switchover_*.tar.gz
  4. ./trigger_failover.sh             # Test failure scenario
  5. Review logs in failover_*.tar.gz
  6. docker start patroni2             # Recover from failover

OPTION B - Continuous Monitoring:
  1. nohup ./monitor_and_collect.sh > monitor.log 2>&1 &
  2. Perform manual operations on cluster
  3. Logs automatically captured on events
  4. pkill -f monitor_and_collect.sh   # Stop when done

OPTION C - Manual Control:
  1. ./collect_patroni_logs.sh
  2. Manually trigger switchover/failover
  3. Press Enter to complete collection
  4. Review logs in event_*.tar.gz
